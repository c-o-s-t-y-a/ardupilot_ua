# MSP OSD

> Оригінал: [MSP OSD](https://ardupilot.org/copter/docs/common-msp-osd-overview-4.2.html)

ArduPilot підтримує кілька типів OSD (накладення даних на відео) на основі протоколів MSP (MultiWii Serial Protocol):

<!-- terms-ignore: FPV -->
- OSD на основі MSP telemetry (телеметрія), як-от окуляри DJI FPV Goggles V1/V2, DJI Goggles RE, FatShark ByteFrost, FatShark SharkByte (firmware (прошивка) до 09042021), старі версії [MWOSD](http://www.mwosd.com/) (новіші версії підтримують MAVLink, див. [MinimOSD](https://ardupilot.org/copter/docs/common-minim-osd-quick-installation-guide.html) *(ще не перекладено)*) тощо.
- OSD на основі [DisplayPort](https://ardupilot.org/copter/docs/common-displayport.html) *(ще не перекладено)*, як-от HDZero (раніше — FatShark SharkByte з firmware 09042021 і новішою), Walksnail, окуляри DJI з firmware [wtf-os](https://github.com/fpv-wtf/wtfos) і модулем [msdp-osd](https://github.com/fpv-wtf/msp-osd), а також режим/firmware DisplayPort у MWOSD.

OSD, що працюють лише на telemetry, малюють елементи панелі OSD на екрані власним рушієм на основі стандартних повідомлень MSP telemetry з даними датчиків, які надсилаються протоколом UART (послідовний порт) «32», тож ArduPilot ніяк не впливає на вигляд елементів.

Окуляри DJI 2/V1/V2 мають також розширений протокол, що надсилається протоколом UART «33». Він передає позицію кожної панелі OSD під час використання їхньої розширеної функції Custom OSD. Це також дає змогу показувати будь-яку панель OSD ArduPilot.

DisplayPort, навпаки, — розширення протоколу MSP, яке дає ArduPilot змогу задавати текстові символи/значки та їхні позиції для малювання на зовнішніх дисплеях OSD так само, як на вбудованих аналогових OSD, за допомогою протоколу UART «42». DisplayPort також (неправильно) називають CANVAS MODE. По суті це віддалений суто текстовий буфер кадру, що використовує локальні шрифти (локальні для рушія відображення, тобто для обладнання OSD), щоб малювати рядки, надіслані через MSP.

## OSD на основі telemetry

OSD на основі telemetry малюють елементи панелі OSD на екрані власним рушієм, тож ArduPilot ніяк не впливає на вигляд елементів. Ще одне обмеження таких OSD — ArduPilot не може довільно додавати нові елементи панелі; додавати нові функції через випуски нової firmware — відповідальність виробника.

Якщо є бортовий вбудований аналоговий OSD і користувач хоче мати обидва OSD, його теж можна активувати. Наприклад, на апаратах, що використовують систему окулярів/повітряного модуля DJI для середньої дальності, але мають ще й аналоговий VTX (відеопередавач) далекої дальності з вбудованим OSD — на випадок, коли апарат виходить за межі дальності HD-окулярів DJI. У такій конфігурації один екран OSD можна оптимізувати під окуляри DJI, а інший — під вбудований OSD, і перемикатися між ними залежно від того, яку відеосистему зараз переглядаєте.

### Конфігурація

У прикладі повітряний модуль підключено до SERIAL2 flight controller (польотний контролер).

- `OSD_TYPE` = 3, якщо вбудований OSD не використовується, або = 1, якщо вбудований OSD є і користувач хоче мати обидва OSD.
- `SERIAL2_PROTOCOL` = 32 (MSP)
- `SERIAL2_BAUD` = 115
- `MSP_OPTIONS` bit 0 = 0 (не вмикати EnableTelemetryMode), якщо повітряний модуль під'єднано обома лініями RX і TX до TX/RX UART autopilot (автопілот). Встановіть bit 0 = 1 (EnableTelemetryMode), якщо окремий модуль OSD під'єднано лише одним проводом від його входу RX до TX UART. Це називають режимом «push».

### Панелі OSD, доступні в OSD на MSP telemetry

Це елементи OSD лише для MSP, які підтримуються в OSD на основі telemetry (за умови, що сам OSD уміє показувати ці значення telemetry):

| Параметр OSD | Примітки |
|---|---|
| `OSDn_ALTITUDE` | Висота відносно Home |
| `OSDn_ARMING` | Стан arm (переведення в робочий стан): приховано в стані armed (у робочому стані), інакше показує **DISARMED** |
| `OSDn_ASPEED` | Як увімкнути показ повітряної швидкості, див. `OSDn_GSPEED` |
| `OSDn_BAT_VOLT` | Напруга першої батареї |
| `OSDn_BATBAR` | Залишок першої батареї у відсотках у вигляді шкали, на основі заявленої ємності та спожитих мА·год |
| `OSDn_BATUSED` | Спожиті мА·год першої батареї |
| `OSDn_CELLVOLT` | Середня напруга банки першої батареї; якщо автоматичне визначення кількості банок не спрацьовує, задайте її вручну через `MSP_OSD_NCELLS` |
| `OSDn_CLK` | Годинник реального часу (потрібна фіксація GPS; в оригіналі — «GPX fix») |
| `OSDn_CRSSHAIR` | Штучний горизонт не підтримується, тому перехрестя зазвичай приховують |
| `OSDn_CURRENT` | Струм першої батареї |
| `OSDn_ESCTEMP` | В окулярах DJI V1/V2 показує найвищу температуру ESC (електронний регулятор обертів) |
| `OSDn_FLTMODE` | Обладнання DJI не підтримує flight mode (польотний режим) ArduPilot! Цей елемент зазвичай порожній і показує лише !FS! під час failsafe (аварійний захист)! |
| `OSDn_GPSLAT` | Широта GPS у десятковому форматі |
| `OSDn_GPSLONG` | Довгота GPS у десятковому форматі |
| `OSDn_GSPEED` | Показує швидкість відносно землі, якщо лише не `OSDn_ASPEED_EN` = 1 — тоді показує справжню повітряну швидкість, якщо є датчик повітряної швидкості, або оцінену повітряну швидкість в іншому разі. Позиція на екрані задається `OSDn_GSPEED_X` і `OSDn_GSPEED_Y` незалежно від значення `OSDn_ASPEED_EN` |
| `OSDn_HEADING` | Не підтримується окулярами DJI V1/V2 |
| `OSDn_HOMEDIR` | Стрілка, що обертається і вказує на Home |
| `OSDn_HOMEDIST` | Відстань до Home |
| `OSDn_HORIZON` | Не підтримується окулярами DJI V1/V2 |
| `OSDn_MESSAGE` | Показує текстові повідомлення про стан як біжучий рядок. Повідомлення зникають за кілька секунд, і панель показує поточний flight mode. Якщо `OSDn_WIND_EN` = 1, цей елемент також показує дані про вітер поруч із поточним flight mode у вигляді стрілки, що обертається, і швидкості. |
| `OSDn_PITCH` | Кут pitch (тангаж) |
| `OSDn_POWER` | Миттєва потужність, обчислена як напруга × струм |
| `OSDn_ROLL` | Кут roll (крен) |
| `OSDn_RSSI` | RSSI, як налаштовано в `RSSI_TYPE` |
| `OSDn_SATS` | В окулярах DJI V1/V2, коли немає фіксації GPS для OSD на MSP telemetry (в оригіналі — «OSDfix»), показує 14 супутників; це відома помилка DJI |
| `OSDn_SIDEBARS` | Не підтримується окулярами DJI V1/V2 |
| `OSDn_VSPEED` | Вертикальна швидкість |
| `OSDn_WIND` | Як показувати швидкість і напрямок вітру, див. `OSDn_MESSAGE` |

Окуляри DJI у стандартному режимі відображення OSD підтримують показ MSP telemetry з такими примітками:

<!-- terms-ignore: FPV -->
- ArduPilot наразі підтримує всі елементи панелі OSD, які надають окуляри DJI FPV Goggles V1 і V2, як наведено в таблиці вище.
- Одиниці відображення, окрім метричних та імперських, наразі не підтримуються.
- Підтримуються кілька екранів і дистанційне перемикання між ними.
- Підтримується показ статистики на окремому екрані, подробиці див. нижче.
- Рівні попереджень для RSSI, напруги тощо наразі не підтримуються.

## Окуляри DJI 2/V1/V2 без модифікацій WTFOS

Окрім власного показу OSD лише на MSP telemetry, у новіших моделях з'явилася функція «Custom OSD», яка дає змогу показувати й розміщувати будь-які чи всі інформаційні панелі OSD, що надає ArduPilot, а також попередження, одиниці тощо.

### Конфігурація

Щоб її увімкнути, встановіть такі параметри (приклад для порту SERIAL2, до якого повітряний модуль DJI під'єднано обома лініями TX і RX):

- `OSD_TYPE` = 3, якщо вбудований OSD не використовується, щоб активувати код OSD. Якщо вбудований OSD є і користувач хоче мати обидва OSD, то `OSD_TYPE` = 1 активує бортовий OSD і водночас надасть екрани для функції MSP OSD. Наприклад, на апаратах, що використовують систему окулярів/повітряного модуля DJI для середньої дальності, але мають ще й VTX далекої дальності з вбудованим OSD — на випадок, коли апарат виходить за межі дальності HD-окулярів DJI. У такій конфігурації один екран OSD можна оптимізувати під окуляри DJI, а інший — під вбудований OSD, і перемикатися між ними залежно від того, яку відеосистему зараз переглядаєте.
- `SERIAL2_PROTOCOL` = 33 (**DJI FPV**)
- `SERIAL2_BAUD` = 115
- `MSP_OPTIONS` bit 0 = 0 (не вмикати EnableTelemetryMode)
- `MSP_OPTIONS` bit 2 = 1 (EnableBTFLFonts) змушує ArduPilot видавати себе за Betaflight і використовувати сумісний з Betaflight індекс шрифту для таблиці шрифтів, вбудованої у віддалену систему OSD. Це потрібно, бо в окулярах немає таблиці шрифтів, сумісної з ArduPilot.
- `OSD_OPTIONS` bit 5 = 1 (TranslateArrows) — використовувати виправлені стрілки напрямку з шрифтами Betaflight.

> **Примітка.** Коли задаєте наведений вище тип протоколу, типова швидкість UART автоматично змінюється на 115,2 кбод. Проте якщо користувач раніше змінив швидкість або змінить її згодом, це типове значення не використовуватиметься. Швидкість 115,2 кбод потрібна більшості систем відеоокулярів.

> **Примітка.** DJI Custom OSD має бути ввімкнено в меню окулярів **SETTINGS->DISPLAY->CUSTOM OSD**.

## Налаштування розкладки в Mission Planner

Mission Planner (MP) має в меню **CONFIG** вкладку для налаштування бортового OSD, вбудованого в багато autopilot, а також для розкладок OSD DisplayPort. Цю ж вкладку можна використовувати для налаштування панелей OSD.

> **Примітка.** Екран налаштування OSD у Mission Planner тепер підтримує конфігурацію HD OSD. Щоб її ввімкнути, позначте **HD Layout** в **Editor Options** угорі праворуч на екрані OSD, який хочете змінити.

![MissionPlanner_OSD_HD](https://ardupilot.org/copter/_images/MissionPlanner_OSD_HD.gif)

Змінювати конфігурацію відображення MSP OSD можна, підключивши Mission Planner до SITL, поки активне вікно емуляції MSP OSD. Так можна налаштовувати й допрацьовувати конфігурацію OSD у SITL, не турбуючись про перегрів VTX. Коли закінчите, перенесіть обрані параметри OSD на свій апарат.

Mission Planner, запущений на тому ж комп'ютері або на комп'ютері в мережі, можна підключити до MAVProxy такою командою в MAVProxy:

```
output add <ip address of box running Mission Planner>:14550
```

> **Примітка.** Якщо MP працює на тому ж ПК, IP-адреса буде 127.0.0.1 (адреса localhost).

Докладніше про використання Mission Planner із SITL див. [документацію бортового OSD з SITL](osd.md). *(В оригіналі посилання веде на якір `testing-osd-with-sitl`, якого на сторінці OSD наразі немає.)*
