# Обмеження firmware (прошивки) на різних autopilot

> Оригінал: [Firmware Limitations on AutoPilot Hardware](https://ardupilot.org/copter/docs/common-limited-firmware.html)

Firmware (прошивка) ArduPilot у деяких конфігураціях займає понад 1 MB. На деяких autopilot (автопілот) може не вистачити flash (флеш-пам'ять), щоб зберегти повну firmware.

Для таких autopilot збирається скорочена firmware. Вона не містить рідше вживаних функцій, щоб розмір firmware не перевищував 1 MB.

<del>[Відсутні функції перелічено на цій сторінці](https://ardupilot.org/copter/docs/binary-features.html) для кожного типу плати для поточної firmware «latest». Якщо вам потрібна якась із цих функцій, можна спробувати створити збірку з нею (коштом інших непотрібних функцій) на [Custom Firmware Build Server](https://custom.ardupilot.org). Відсутні функції плати перелічено тими самими групами й назвами, що й на Custom Firmware Build Server.</del>

> **Примітка.** Зараз наведена вище сторінка відсутніх функцій генерується автоматично і містить помилку. Поки це досліджують і виправляють, точний перелік для конкретної плати й версії firmware можна знайти у файлі «features.txt» у каталозі її firmware на [сервері firmware](https://firmware.ardupilot.org/).

Щоб користуватися сервером, треба знати, які функції вам ПОТРІБНІ, і позначити їх, а також ті бажані, яких зараз бракує. Таблицю всіх поточних опцій збірки, які можна вибрати, наведено [тут](https://ardupilot.org/copter/docs/binary-features.html#all-features) *(ще не перекладено)*.

## Обмеження RAM

На деяких autopilot може не вистачати RAM для всіх увімкнених функцій firmware. Можливі симптоми:

- Не працює MAVFTP. Завантаження параметрів у GCS (наземна станція керування) починається із затримкою, поки GCS намагається встановити з'єднання MAVFTP, яке встановити неможливо, а потім параметри повільно завантажуються звичайним способом.
- Не запускається калібрування compass (компас).
- Не запускається запис log (журнал польоту).
- Не запускається завантаження рельєфу (terrain) з GCS.
- Не ініціалізуються інтерфейси, наприклад CAN: «Failed to initialise CAN Interface xx».

У такому разі є кілька варіантів, як тимчасово скористатися MAVFTP, завантажити фрагменти рельєфу, дозволити завантаження драйвера та/або виконати калібрування compass. Усі вони набувають чинності після перезавантаження:

- Переконайтеся, що пакетний запис IMU (інерційний вимірювальний модуль) (IMU Batch Sampling, використовується для FFT-аналізу) не працює: встановіть `INS_LOG_BAT_MASK` = 0.
- Спробуйте тимчасово вимкнути запис log, встановивши `LOG_BACKEND_TYPE` у 0, а після калібрування повернувши 1 (за замовчуванням).
- Зменште `LOG_FILE_BUFSIZE`. Проте значення нижче 16KB можуть спричинити невеликі пропуски в log. Можна використати це тимчасово, щоб завантажити рельєф чи відкалібрувати compass.
- Тимчасово вимкніть політ за рельєфом (Terrain Following), встановивши `TERRAIN_ENABLE` у 0.
- Вимкніть SmartRTL на Copter: `SRTL_POINTS` = 0.
- Якщо використовується DroneCAN, спробуйте зменшити виділення пам'яті зі стандартних 16KB (для двох вузлів) параметрами `CAN_Dx_UC_POOL`.

> **Примітка.** На вкладці STATUS у Mission Planner можна стежити за значенням «freemem» — поточним обсягом вільної RAM. Майте на увазі, що це загальний обсяг невиділеної пам'яті, а все, що потребує виділення пам'яті, потребує одного суцільного блоку. Та все ж цей показник дає уявлення про доступну пам'ять. Наприклад, для запуску MAVftp потрібен суцільний блок ~12K.
